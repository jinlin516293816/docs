安全架构 ​

前端安全的重要性 ​

前端安全问题可能导致：

  • 数据泄露：用户隐私信息暴露
  • 账户被盗：会话劫持、凭证窃取
  • 恶意操作：XSS 攻击、CSRF 攻击
  • 信誉损失：用户信任度下降

常见安全威胁 ​

OWASP Top 10（前端相关） ​

  1. XSS (Cross-Site Scripting) - 跨站脚本攻击
  2. CSRF (Cross-Site Request Forgery) - 跨站请求伪造
  3. 敏感数据泄露
  4. 失效的访问控制
  5. 安全配置错误

XSS 攻击防护 ​

什么是 XSS？ ​

攻击者通过注入恶意脚本，在用户浏览器中执行。

类型：

  • 反射型 XSS：通过 URL 参数注入
  • 存储型 XSS：恶意脚本存储在服务器
  • DOM 型 XSS：通过 DOM 操作注入

攻击示例 ​

javascript
// ❌ 危险的代码
const userInput = location.search.split('=')[1]
document.getElementById('output').innerHTML = userInput

// 攻击 URL
// https://example.com?name=<script>alert('XSS')</script>

1. CSRF Token ​

// 生成 Token
function generateCsrfToken() {
  const token = Math.random().toString(36).substr(2)
  sessionStorage.setItem('csrf_token', token)
  return token
}

// 添加到请求头
axios.interceptors.request.use(config => {
  const token = sessionStorage.getItem('csrf_token')
  if (token) {
    config.headers['X-CSRF-Token'] = token
  }
  return config
})

// Express 中间件
function csrfProtection(req, res, next) {
  const token = req.headers['x-csrf-token']
  const sessionToken = req.session.csrfToken
  
  if (token !== sessionToken) {
    return res.status(403).json({ error: 'Invalid CSRF token' })
  }
  next()
}

3. 验证 Referer ​

javascript
function checkReferer(req, res, next) {
  const referer = req.headers.referer
  const host = req.headers.host
  
  if (!referer || !referer.includes(host)) {
    return res.status(403).json({ error: 'Invalid referer' })
  }
  next()
}

Token 刷新：

javascript
// composables/useAuth.js
import { ref } from 'vue'
import axios from 'axios'

const token = ref(null)
const refreshTokenTimer = ref(null)

function setToken(newToken) {
  token.value = newToken
  
  // 设置自动刷新
  const payload = JSON.parse(atob(newToken.split('.')[1]))
  const expiresIn = payload.exp * 1000 - Date.now()
  
  // 提前 5 分钟刷新
  refreshTokenTimer.value = setTimeout(() => {
    refreshAccessToken()
  }, expiresIn - 5 * 60 * 1000)
}

async function refreshAccessToken() {
  try {
    const response = await axios.post('/api/auth/refresh')
    setToken(response.data.token)
  } catch (error) {
    // 刷新失败，跳转到登录页
    logout()
  }
}

function logout() {
  token.value = null
  clearTimeout(refreshTokenTimer.value)
  // 清除 Cookie
  document.cookie = 'token=; Max-Age=0'
}

export function useAuth() {
  return { token, setToken, logout }
}

2. 权限控制 ​

路由守卫：

javascript
// router/index.js
import { useUserStore } from '@/stores/user'

router.beforeEach(async (to, from, next) => {
  const userStore = useUserStore()
  
  // 需要认证的路由
  if (to.meta.requiresAuth) {
    if (!userStore.isLoggedIn) {
      next({ name: 'login', query: { redirect: to.fullPath } })
      return
    }
  }
  
  // 需要特定权限的路由
  if (to.meta.permissions) {
    const hasPermission = to.meta.permissions.every(perm => 
      userStore.hasPermission(perm)
    )
    
    if (!hasPermission) {
      next({ name: 'forbidden' })
      return
    }
  }
  
  next()
})

组件级权限：

<!-- composables/usePermission.js -->
import { useUserStore } from '@/stores/user'

export function usePermission() {
  const userStore = useUserStore()
  
  function hasPermission(permission) {
    return userStore.permissions.includes(permission)
  }
  
  function hasRole(role) {
    return userStore.roles.includes(role)
  }
  
  return { hasPermission, hasRole }
}

<!-- 使用 -->
<script setup>
import { usePermission } from '@/composables/usePermission'

const { hasPermission } = usePermission()
</script>

<template>
  <button v-if="hasPermission('user:edit')">编辑</button>
  <button v-if="hasPermission('user:delete')">删除</button>
</template>

输入验证 ​

1. 前端验证 ​

javascript
// utils/validator.js
export const validators = {
  required: (value) => {
    if (!value) return '此字段为必填项'
    return true
  },
  
  email: (value) => {
    const pattern = /^[^\s@]+@[^\s@]+\.[^\s@]+$/
    if (!pattern.test(value)) return '请输入有效的邮箱地址'
    return true
  },
  
  phone: (value) => {
    const pattern = /^1[3-9]\d{9}$/
    if (!pattern.test(value)) return '请输入有效的手机号'
    return true
  },
  
  minLength: (min) => (value) => {
    if (value.length < min) return `最少 ${min} 个字符`
    return true
  },
  
  maxLength: (max) => (value) => {
    if (value.length > max) return `最多 ${max} 个字符`
    return true
  }
}

// 使用
import { validators } from '@/utils/validator'

const rules = {
  username: [validators.required, validators.minLength(3)],
  email: [validators.required, validators.email],
  phone: [validators.required, validators.phone]
}

安全 Headers ​

Nginx 配置 ​

nginx
server {
  # HSTS - 强制 HTTPS
  add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
  
  # X-Frame-Options - 防止点击劫持
  add_header X-Frame-Options "DENY" always;
  
  # X-Content-Type-Options - 防止 MIME 类型嗅探
  add_header X-Content-Type-Options "nosniff" always;
  
  # X-XSS-Protection - XSS 保护
  add_header X-XSS-Protection "1; mode=block" always;
  
  # Referrer-Policy - 控制 Referer 信息
  add_header Referrer-Policy "strict-origin-when-cross-origin" always;
  
  # Permissions-Policy - 控制浏览器功能
  add_header Permissions-Policy "geolocation=(), microphone=(), camera=()" always;
}

安全审计清单 ​

开发阶段 ​

  • [ ] 所有用户输入都经过验证和转义
  • [ ] 不使用 eval() 和 innerHTML
  • [ ] 敏感数据不存储在前端
  • [ ] 使用 HTTPS
  • [ ] Token 安全存储

测试阶段 ​

  • [ ] 进行 XSS 测试
  • [ ] 进行 CSRF 测试
  • [ ] 检查依赖漏洞
  • [ ] 验证权限控制
  • [ ] 测试输入验证

部署阶段 ​

  • [ ] 配置安全 Headers
  • [ ] 启用 CSP
  • [ ] 关闭调试模式
  • [ ] 移除 sourcemap
  • [ ] 定期更新依赖

运维阶段 ​

  • [ ] 监控异常行为
  • [ ] 定期安全审计
  • [ ] 及时修补漏洞
  • [ ] 备份重要数据
  • [ ] 制定应急响应计划

最佳实践总结 ​

核心原则 ​

✅ 永不信任用户输入 - 始终验证和转义 ✅ 最小权限原则 - 只授予必要的权限 ✅ 纵深防御 - 多层安全防护 ✅ 定期更新 - 保持依赖最新 ✅ 安全默认 - 默认拒绝，显式允许

关键措施 ​

  1. XSS 防护

    • 转义输出
    • 使用 CSP
    • HttpOnly Cookie

  2. CSRF 防护

    • CSRF Token
    • SameSite Cookie
    • 验证 Referer

  3. 数据安全

    • HTTPS 传输
    • 加密存储
    • 不暴露敏感信息

  4. 认证授权

    • JWT Token 管理
    • 路由守卫
    • 权限控制

  5. 依赖安全

    • 定期审计
    • 锁定版本
    • 监控漏洞

记住：安全是一个持续的过程，不是一次性的任务
