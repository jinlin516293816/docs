状态管理架构 ​

为什么需要状态管理？ ​

随着应用复杂度增加，组件间的数据流动变得复杂：

❌ 没有状态管理时：
Parent → Child1 → GrandChild1
     ↘ Child2 → GrandChild2
     ↘ Child3
     
数据传递混乱，难以维护

4

状态管理解决的问题：

  • ✅ 全局状态共享
  • ✅ 数据流可预测
  • ✅ 便于调试和测试
  • ✅ 组件解耦

状态管理方案对比 ​

1. Vuex（Vue 2/3） ​

特点：

  • 官方推荐
  • 集中式存储
  • 严格的 mutation 流程

核心概念：

State → Getters → Mutations → Actions
   ↑                              ↓
   └──────── Components ──────────┘

示例：

javascript
// store/index.js
import { createStore } from 'vuex'

export default createStore({
  state: {
    count: 0,
    user: null
  },
  
  getters: {
    doubleCount: (state) => state.count * 2,
    isLoggedIn: (state) => !!state.user
  },
  
  mutations: {
    INCREMENT(state) {
      state.count++
    },
    SET_USER(state, user) {
      state.user = user
    }
  },
  
  actions: {
    async login({ commit }, credentials) {
      const user = await api.login(credentials)
      commit('SET_USER', user)
    }
  }
})

2. Pinia（Vue 3 推荐） ​

特点：

  • Vue 3 官方推荐
  • 更简洁的 API
  • 更好的 TypeScript 支持
  • 无 mutations，只有 state、getters、actions

示例：

javascript
// stores/counter.js
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'

export const useCounterStore = defineStore('counter', () => {
  // State
  const count = ref(0)
  const name = ref('Counter')
  
  // Getters
  const doubleCount = computed(() => count.value * 2)
  
  // Actions
  function increment() {
    count.value++
  }
  
  function reset() {
    count.value = 0
  }
  
  return { count, name, doubleCount, increment, reset }
})

import { configureStore, createSlice } from '@reduxjs/toolkit'

const counterSlice = createSlice({
  name: 'counter',
  initialState: { value: 0 },
  reducers: {
    increment: (state) => {
      state.value += 1
    },
    decrement: (state) => {
      state.value -= 1
    }
  }
})

export const { increment, decrement } = counterSlice.actions

export const store = configureStore({
  reducer: {
    counter: counterSlice.reducer
  }
})

状态管理架构设计 ​

1. 状态分类 ​

┌─────────────────────────┐
│     Global State        │  ← 全局状态（用户信息、主题等）
├─────────────────────────┤
│   Module State          │  ← 模块状态（商品、订单等）
├─────────────────────────┤
│   Component State       │  ← 组件状态（表单、UI 状态）
├─────────────────────────┤
│   Local State           │  ← 局部状态（临时变量）
└─────────────────────────┘

决策原则：

  • 多个组件需要 → 全局状态
  • 单个模块内使用 → 模块状态
  • 单个组件使用 → 组件状态
  • 临时计算 → 局部状态

javascript
import { defineStore } from 'pinia'
import { ref, computed } from 'vue'
import { userApi } from '@/api'

export const useUserStore = defineStore('user', () => {
  // State
  const userInfo = ref(null)
  const token = ref(localStorage.getItem('token') || '')
  const permissions = ref([])
  
  // Getters
  const isLoggedIn = computed(() => !!token.value)
  const userName = computed(() => userInfo.value?.name || '')
  const avatar = computed(() => userInfo.value?.avatar || '')
  const hasPermission = computed(() => (perm) => {
    return permissions.value.includes(perm)
  })
  
  // Actions
  async function login(credentials) {
    try {
      const res = await userApi.login(credentials)
      token.value = res.token
      userInfo.value = res.user
      permissions.value = res.permissions
      localStorage.setItem('token', res.token)
    } catch (error) {
      throw error
    }
  }
  
  function logout() {
    token.value = ''
    userInfo.value = null
    permissions.value = []
    localStorage.removeItem('token')
  }
  
  async function updateProfile(data) {
    await userApi.update(userInfo.value.id, data)
    userInfo.value = { ...userInfo.value, ...data }
  }
  
  async function fetchPermissions() {
    const perms = await userApi.getPermissions()
    permissions.value = perms
  }
  
  return {
    userInfo,
    token,
    permissions,
    isLoggedIn,
    userName,
    avatar,
    hasPermission,
    login,
    logout,
    updateProfile,
    fetchPermissions
  }
})

高级用法 ​

1. 持久化存储 ​

使用 pinia-plugin-persistedstate：

javascript
// stores/cart.js
import { defineStore } from 'pinia'
import { ref } from 'vue'

export const useCartStore = defineStore('cart', () => {
  const items = ref([])
  
  function addItem(product) {
    items.value.push(product)
  }
  
  function removeItem(productId) {
    const index = items.value.findIndex(i => i.id === productId)
    if (index > -1) {
      items.value.splice(index, 1)
    }
  }
  
  return { items, addItem, removeItem }
}, {
  persist: {
    storage: localStorage,
    paths: ['items'] // 只持久化 items
  }
})

2. 异步 Action ​

javascript
export const useProductStore = defineStore('product', () => {
  const products = ref([])
  const loading = ref(false)
  const error = ref(null)
  
  async function fetchProducts(params = {}) {
    loading.value = true
    error.value = null
    
    try {
      const res = await productApi.list(params)
      products.value = res.data
    } catch (err) {
      error.value = err.message
    } finally {
      loading.value = false
    }
  }
  
  async function createProduct(data) {
    try {
      const newProduct = await productApi.create(data)
      products.value.push(newProduct)
      return newProduct
    } catch (err) {
      error.value = err.message
      throw err
    }
  }
  
  return {
    products,
    loading,
    error,
    fetchProducts,
    createProduct
  }
})

3. Store 组合 ​

javascript
// stores/order.js
import { defineStore } from 'pinia'
import { useCartStore } from './cart'
import { useUserStore } from './user'

export const useOrderStore = defineStore('order', () => {
  const cartStore = useCartStore()
  const userStore = useUserStore()
  
  async function createOrder() {
    if (!userStore.isLoggedIn) {
      throw new Error('请先登录')
    }
    
    if (cartStore.items.length === 0) {
      throw new Error('购物车为空')
    }
    
    const orderData = {
      userId: userStore.userInfo.id,
      items: cartStore.items,
      total: cartStore.total
    }
    
    const order = await orderApi.create(orderData)
    
    // 清空购物车
    cartStore.clear()
    
    return order
  }
  
  return { createOrder }
})

3. 缓存计算结果 ​

javascript
export const useProductStore = defineStore('product', () => {
  const products = ref([])
  
  // 使用 computed 缓存计算结果
  const filteredProducts = computed(() => {
    return products.value.filter(p => p.inStock)
  })
  
  const totalPrice = computed(() => {
    return filteredProducts.value.reduce((sum, p) => sum + p.price, 0)
  })
  
  return { products, filteredProducts, totalPrice }
})

javascript
// 插件记录所有 action
export const loggerPlugin = (context) => {
  context.store.$onAction(({ name, store, args, after, onError }) => {
    console.group(`Action: ${name}`)
    console.log('Arguments:', args)
    
    after((result) => {
      console.log('Result:', result)
      console.groupEnd()
    })
    
    onError((error) => {
      console.error('Error:', error)
      console.groupEnd()
    })
  })
}

// 使用插件
pinia.use(loggerPlugin)

3. 状态快照 ​

javascript
// 保存状态快照
function saveSnapshot() {
  const snapshot = JSON.stringify({
    user: useUserStore().$state,
    cart: useCartStore().$state
  })
  localStorage.setItem('state-snapshot', snapshot)
}

// 恢复状态
function restoreSnapshot() {
  const snapshot = localStorage.getItem('state-snapshot')
  if (snapshot) {
    const state = JSON.parse(snapshot)
    useUserStore().$state = state.user
    useCartStore().$state = state.cart
  }
}

总结 ​

状态管理架构的关键点：

✅ 选择合适的方案 - Pinia（Vue 3）、Redux（React） ✅ 合理划分状态 - 全局、模块、组件、局部 ✅ 模块化组织 - 按业务模块拆分 store ✅ 处理副作用 - 异步操作、持久化 ✅ 性能优化 - 避免不必要的更新 ✅ 调试友好 - Devtools、日志、快照

记住：不是所有状态都需要放入全局 store，合理使用本地状态更重要。
