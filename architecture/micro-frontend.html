微前端架构 ​

什么是微前端？ ​

微前端（Micro-Frontends）是一种将前端应用拆分成多个独立子应用的架构风格。每个子应用可以：

  • 独立开发：不同的团队负责不同的子应用
  • 独立部署：子应用可以单独发布更新
  • 技术栈无关：不同子应用可以使用不同的框架
  • 增量升级：逐步迁移老项目，无需重写

为什么需要微前端？ ​

微前端核心方案 ​

1. qiankun（阿里） ​

基于 single-spa 的微前端框架。

特点：

  • HTML Entry 加载方式
  • 样式隔离
  • JS 沙箱
  • 资源预加载

使用示例：

主应用配置：

javascript
// main.js
import { registerMicroApps, start } from 'qiankun'

registerMicroApps([
  {
    name: 'reactApp',
    entry: '//localhost:3000',
    container: '#container',
    activeRule: '/react',
  },
  {
    name: 'vueApp',
    entry: '//localhost:8080',
    container: '#container',
    activeRule: '/vue',
  },
])

start()

2. Module Federation（Webpack 5） ​

Webpack 5 原生支持的模块联邦。

特点：

  • 运行时共享依赖
  • 双向通信
  • 更好的性能

配置示例：

主应用：

javascript
// webpack.config.js
module.exports = {
  plugins: [
    new ModuleFederationPlugin({
      name: 'host',
      remotes: {
        remoteApp: 'remoteApp@http://localhost:3001/remoteEntry.js',
      },
      shared: {
        react: { singleton: true },
        'react-dom': { singleton: true },
      },
    }),
  ],
}

常见问题 ​

解决方案：

  2. Shadow DOM

解决方案：

  3. externals + CDN

总结 ​

微前端架构适合：

  • ✅ 大型复杂应用
  • ✅ 多团队协作
  • ✅ 技术栈多样化
  • ✅ 渐进式重构

不适合：

  • ❌ 小型简单应用
  • ❌ 单一团队维护
  • ❌ 性能要求极高

选择合适的方案，合理规划架构，才能让微前端发挥最大价值。
