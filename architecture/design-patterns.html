设计模式详解 ​

一、设计模式概述 ​

设计模式是软件设计中反复出现问题的解决方案，是经验的总结和最佳实践的体现。

设计模式的分类 ​

类别目的包含模式
创建型模式处理对象创建机制工厂、抽象工厂、单例、建造者、原型
结构型模式处理对象组合关系适配器、装饰器、代理、外观、桥接、组合、享元
行为型模式处理对象间通信观察者、策略、命令、职责链、模板方法、迭代器、状态、访问者

设计原则 ​

  1. 单一职责原则：一个类只负责一个职责
  2. 开闭原则：对扩展开放，对修改关闭
  3. 里氏替换原则：子类可以替换父类
  4. 依赖倒置原则：依赖抽象而非具体实现
  5. 接口隔离原则：接口应该小而专
  6. 迪米特法则：最少知识原则

二、创建型模式 ​

1. 工厂模式（Factory Pattern） ​

含义：定义一个创建对象的接口，让子类决定实例化哪个类。

实现原理：

  • 将对象创建逻辑封装在工厂类中
  • 客户端通过工厂获取对象，无需关心具体实现

场景应用：

  • 对象创建复杂，需要统一管理
  • 需要解耦对象创建和使用

代码示例：

javascript
// 产品接口
class Product {
  constructor(name) {
    this.name = name;
  }
  operation() {}
}

// 具体产品
class ConcreteProductA extends Product {
  operation() {
    return `ProductA: ${this.name}`;
  }
}

class ConcreteProductB extends Product {
  operation() {
    return `ProductB: ${this.name}`;
  }
}

// 工厂类
class Factory {
  createProduct(type, name) {
    switch (type) {
      case 'A':
        return new ConcreteProductA(name);
      case 'B':
        return new ConcreteProductB(name);
      default:
        throw new Error('Unknown product type');
    }
  }
}

// 使用
const factory = new Factory();
const productA = factory.createProduct('A', 'Test');
console.log(productA.operation()); // ProductA: Test

2. 抽象工厂模式（Abstract Factory Pattern） ​

含义：提供一个接口，用于创建相关或依赖对象的家族，而不需要明确指定具体类。

场景应用：

  • 需要创建一组相关对象
  • 系统需要独立于产品的创建和组合方式

代码示例：

javascript
// 抽象产品
class Button { render() {} }
class Checkbox { render() {} }

// 具体产品 - Windows风格
class WindowsButton extends Button {
  render() { return 'Windows Button'; }
}
class WindowsCheckbox extends Checkbox {
  render() { return 'Windows Checkbox'; }
}

// 具体产品 - Mac风格
class MacButton extends Button {
  render() { return 'Mac Button'; }
}
class MacCheckbox extends Checkbox {
  render() { return 'Mac Checkbox'; }
}

// 抽象工厂
class GUIFactory {
  createButton() {}
  createCheckbox() {}
}

// 具体工厂
class WindowsFactory extends GUIFactory {
  createButton() { return new WindowsButton(); }
  createCheckbox() { return new WindowsCheckbox(); }
}

class MacFactory extends GUIFactory {
  createButton() { return new MacButton(); }
  createCheckbox() { return new MacCheckbox(); }
}

// 使用
const factory = new WindowsFactory();
const button = factory.createButton();
const checkbox = factory.createCheckbox();

3. 单例模式（Singleton Pattern） ​

含义：确保一个类只有一个实例，并提供全局访问点。

实现原理：

  • 私有化构造函数
  • 提供静态方法获取实例
  • 确保只创建一次

场景应用：

  • 全局状态管理
  • 日志记录器
  • 数据库连接池

代码示例：

javascript
// ES6 单例实现
class Singleton {
  constructor() {
    if (Singleton.instance) {
      return Singleton.instance;
    }
    Singleton.instance = this;
    this.value = 0;
  }

  getValue() {
    return this.value;
  }

  setValue(val) {
    this.value = val;
  }
}

// 使用
const instance1 = new Singleton();
const instance2 = new Singleton();
console.log(instance1 === instance2); // true

4. 建造者模式（Builder Pattern） ​

含义：将复杂对象的构建过程与其表示分离，使同样的构建过程可以创建不同的表示。

场景应用：

  • 对象创建复杂，有多个参数
  • 需要分步构建对象

代码示例：

javascript
class Product {
  constructor() {
    this.parts = [];
  }

  addPart(part) {
    this.parts.push(part);
  }

  listParts() {
    return this.parts.join(', ');
  }
}

class Builder {
  constructor() {
    this.product = new Product();
  }

  buildPartA() {
    this.product.addPart('PartA');
    return this;
  }

  buildPartB() {
    this.product.addPart('PartB');
    return this;
  }

  buildPartC() {
    this.product.addPart('PartC');
    return this;
  }

  getResult() {
    return this.product;
  }
}

// 使用
const builder = new Builder();
const product = builder
  .buildPartA()
  .buildPartB()
  .getResult();
console.log(product.listParts()); // PartA, PartB

5. 原型模式（Prototype Pattern） ​

含义：通过复制现有对象来创建新对象，而不是通过实例化类。

场景应用：

  • 对象创建成本高
  • 需要创建多个相似对象

代码示例：

javascript
class Prototype {
  constructor(name) {
    this.name = name;
  }

  clone() {
    return Object.create(Object.getPrototypeOf(this), {
      name: { value: this.name }
    });
  }
}

// 使用
const prototype = new Prototype('Original');
const clone1 = prototype.clone();
const clone2 = prototype.clone();
console.log(clone1.name); // Original
console.log(clone1 === clone2); // false

三、结构型模式 ​

1. 适配器模式（Adapter Pattern） ​

含义：将一个类的接口转换成客户希望的另一个接口，使原本不兼容的类可以协同工作。

场景应用：

  • 集成第三方库
  • 接口不兼容的系统对接

代码示例：

javascript
// 目标接口
class Target {
  request() {
    return 'Target request';
  }
}

// 适配者
class Adaptee {
  specificRequest() {
    return 'Adaptee specific request';
  }
}

// 适配器
class Adapter extends Target {
  constructor(adaptee) {
    super();
    this.adaptee = adaptee;
  }

  request() {
    return this.adaptee.specificRequest();
  }
}

// 使用
const adaptee = new Adaptee();
const adapter = new Adapter(adaptee);
console.log(adapter.request()); // Adaptee specific request

2. 装饰器模式（Decorator Pattern） ​

含义：动态地给对象添加额外职责，而不改变其结构。

场景应用：

  • 需要动态扩展对象功能
  • 避免使用继承带来的类爆炸

代码示例：

javascript
// 组件接口
class Component {
  operation() {}
}

// 具体组件
class ConcreteComponent extends Component {
  operation() {
    return 'ConcreteComponent';
  }
}

// 装饰器基类
class Decorator extends Component {
  constructor(component) {
    super();
    this.component = component;
  }

  operation() {
    return this.component.operation();
  }
}

// 具体装饰器
class ConcreteDecoratorA extends Decorator {
  operation() {
    return `DecoratorA(${super.operation()})`;
  }
}

class ConcreteDecoratorB extends Decorator {
  operation() {
    return `DecoratorB(${super.operation()})`;
  }
}

// 使用
const component = new ConcreteComponent();
const decorated = new ConcreteDecoratorA(new ConcreteDecoratorB(component));
console.log(decorated.operation()); // DecoratorA(DecoratorB(ConcreteComponent))

3. 代理模式（Proxy Pattern） ​

含义：为其他对象提供一个代理，以控制对这个对象的访问。

场景应用：

  • 延迟加载
  • 权限控制
  • 日志记录

代码示例：

javascript
// 真实主题
class RealSubject {
  request() {
    return 'RealSubject request';
  }
}

// 代理
class Proxy {
  constructor() {
    this.realSubject = null;
  }

  request() {
    if (!this.realSubject) {
      this.realSubject = new RealSubject();
    }
    return this.realSubject.request();
  }
}

// 使用
const proxy = new Proxy();
console.log(proxy.request()); // RealSubject request

4. 外观模式（Facade Pattern） ​

含义：提供一个统一的接口，用来访问子系统中的一群接口。

场景应用：

  • 简化复杂系统的调用
  • 提供统一的API入口

代码示例：

javascript
// 子系统
class SubSystemA {
  operationA() { return 'SubSystemA'; }
}

class SubSystemB {
  operationB() { return 'SubSystemB'; }
}

class SubSystemC {
  operationC() { return 'SubSystemC'; }
}

// 外观类
class Facade {
  constructor() {
    this.subA = new SubSystemA();
    this.subB = new SubSystemB();
    this.subC = new SubSystemC();
  }

  operation() {
    return [
      this.subA.operationA(),
      this.subB.operationB(),
      this.subC.operationC()
    ].join(', ');
  }
}

// 使用
const facade = new Facade();
console.log(facade.operation()); // SubSystemA, SubSystemB, SubSystemC

5. 桥接模式（Bridge Pattern） ​

含义：将抽象部分与实现部分分离，使它们可以独立变化。

场景应用：

  • 需要在抽象和实现之间提供更多灵活性
  • 避免多层继承导致的类爆炸

代码示例：

javascript
// 实现接口
class Implementor {
  operationImpl() {}
}

class ConcreteImplementorA extends Implementor {
  operationImpl() { return 'ImplA'; }
}

class ConcreteImplementorB extends Implementor {
  operationImpl() { return 'ImplB'; }
}

// 抽象类
class Abstraction {
  constructor(implementor) {
    this.implementor = implementor;
  }

  operation() {
    return this.implementor.operationImpl();
  }
}

class RefinedAbstraction extends Abstraction {
  operation() {
    return `Refined(${super.operation()})`;
  }
}

// 使用
const implA = new ConcreteImplementorA();
const abstraction = new RefinedAbstraction(implA);
console.log(abstraction.operation()); // Refined(ImplA)

四、行为型模式 ​

1. 观察者模式（Observer Pattern） ​

含义：定义对象间一对多的依赖关系，当一个对象状态改变时，所有依赖者都会收到通知。

场景应用：

  • 发布-订阅系统
  • 状态变更通知
  • 事件监听

代码示例：

javascript
class Subject {
  constructor() {
    this.observers = [];
  }

  attach(observer) {
    this.observers.push(observer);
  }

  detach(observer) {
    this.observers = this.observers.filter(o => o !== observer);
  }

  notify() {
    this.observers.forEach(observer => observer.update());
  }
}

class Observer {
  constructor(name) {
    this.name = name;
  }

  update() {
    console.log(`${this.name} received notification`);
  }
}

// 使用
const subject = new Subject();
const observer1 = new Observer('Observer1');
const observer2 = new Observer('Observer2');

subject.attach(observer1);
subject.attach(observer2);
subject.notify();
// Observer1 received notification
// Observer2 received notification

2. 策略模式（Strategy Pattern） ​

含义：定义一系列算法，把它们封装起来，并使它们可以相互替换。

场景应用：

  • 需要动态切换算法
  • 避免大量条件判断

代码示例：

javascript
// 策略接口
class Strategy {
  execute(data) {}
}

// 具体策略
class ConcreteStrategyA extends Strategy {
  execute(data) {
    return data.sort((a, b) => a - b);
  }
}

class ConcreteStrategyB extends Strategy {
  execute(data) {
    return data.sort((a, b) => b - a);
  }
}

// 上下文
class Context {
  constructor(strategy) {
    this.strategy = strategy;
  }

  setStrategy(strategy) {
    this.strategy = strategy;
  }

  executeStrategy(data) {
    return this.strategy.execute(data);
  }
}

// 使用
const context = new Context(new ConcreteStrategyA());
console.log(context.executeStrategy([3, 1, 2])); // [1, 2, 3]

context.setStrategy(new ConcreteStrategyB());
console.log(context.executeStrategy([3, 1, 2])); // [3, 2, 1]

3. 命令模式（Command Pattern） ​

含义：将请求封装成对象，以便使用不同的请求、队列或日志来参数化其他对象。

场景应用：

  • 撤销/重做功能
  • 任务队列
  • 日志记录

代码示例：

javascript
// 命令接口
class Command {
  execute() {}
  undo() {}
}

// 具体命令
class ConcreteCommand extends Command {
  constructor(receiver) {
    super();
    this.receiver = receiver;
  }

  execute() {
    this.receiver.action();
  }

  undo() {
    this.receiver.undoAction();
  }
}

// 接收者
class Receiver {
  action() {
    console.log('Action executed');
  }

  undoAction() {
    console.log('Action undone');
  }
}

// 调用者
class Invoker {
  constructor() {
    this.commands = [];
  }

  setCommand(command) {
    this.commands.push(command);
  }

  executeCommands() {
    this.commands.forEach(cmd => cmd.execute());
  }

  undoCommands() {
    this.commands.reverse().forEach(cmd => cmd.undo());
  }
}

// 使用
const receiver = new Receiver();
const command = new ConcreteCommand(receiver);
const invoker = new Invoker();

invoker.setCommand(command);
invoker.executeCommands(); // Action executed
invoker.undoCommands();    // Action undone

4. 职责链模式（Chain of Responsibility Pattern） ​

含义：将请求的发送者和接收者解耦，让多个对象都有机会处理请求。

场景应用：

  • 请求需要经过多个处理步骤
  • 不确定哪个对象处理请求

代码示例：

javascript
class Handler {
  constructor() {
    this.nextHandler = null;
  }

  setNext(handler) {
    this.nextHandler = handler;
    return handler;
  }

  handle(request) {
    if (this.nextHandler) {
      return this.nextHandler.handle(request);
    }
    return null;
  }
}

class ConcreteHandlerA extends Handler {
  handle(request) {
    if (request === 'A') {
      return 'HandlerA handled';
    }
    return super.handle(request);
  }
}

class ConcreteHandlerB extends Handler {
  handle(request) {
    if (request === 'B') {
      return 'HandlerB handled';
    }
    return super.handle(request);
  }
}

// 使用
const handlerA = new ConcreteHandlerA();
const handlerB = new ConcreteHandlerB();
handlerA.setNext(handlerB);

console.log(handlerA.handle('A')); // HandlerA handled
console.log(handlerA.handle('B')); // HandlerB handled

5. 模板方法模式（Template Method Pattern） ​

含义：定义算法骨架，将一些步骤延迟到子类中实现。

场景应用：

  • 算法结构固定，但某些步骤可变
  • 需要复用算法框架

代码示例：

javascript
class AbstractClass {
  templateMethod() {
    this.baseOperation1();
    this.requiredOperation1();
    this.baseOperation2();
    this.hook();
  }

  baseOperation1() {
    console.log('Base operation 1');
  }

  baseOperation2() {
    console.log('Base operation 2');
  }

  hook() {}
}

class ConcreteClass extends AbstractClass {
  requiredOperation1() {
    console.log('Concrete operation 1');
  }

  hook() {
    console.log('Concrete hook');
  }
}

// 使用
const concrete = new ConcreteClass();
concrete.templateMethod();
// Base operation 1
// Concrete operation 1
// Base operation 2
// Concrete hook

6. 状态模式（State Pattern） ​

含义：允许对象在内部状态改变时改变行为，使对象看起来好像修改了它的类。

场景应用：

  • 对象行为依赖于状态
  • 状态转换复杂

代码示例：

javascript
class State {
  handle() {}
}

class ConcreteStateA extends State {
  handle(context) {
    console.log('State A');
    context.setState(new ConcreteStateB());
  }
}

class ConcreteStateB extends State {
  handle(context) {
    console.log('State B');
    context.setState(new ConcreteStateA());
  }
}

class Context {
  constructor() {
    this.state = new ConcreteStateA();
  }

  setState(state) {
    this.state = state;
  }

  request() {
    this.state.handle(this);
  }
}

// 使用
const context = new Context();
context.request(); // State A
context.request(); // State B
context.request(); // State A

五、设计模式总结 ​

选择合适的设计模式 ​

问题场景推荐模式
对象创建复杂工厂模式、建造者模式
需要全局唯一实例单例模式
接口不兼容适配器模式
需要动态扩展功能装饰器模式
需要控制访问代理模式
简化复杂系统外观模式
状态变更通知观察者模式
算法动态切换策略模式
撤销/重做功能命令模式
请求链式处理职责链模式

设计模式的价值 ​

  1. 代码复用：避免重复造轮子
  2. 可维护性：提高代码可读性和可维护性
  3. 可扩展性：便于添加新功能
  4. 解耦合：降低模块间依赖

掌握设计模式是成为高级工程师的必经之路，需要在实践中不断理解和应用。
