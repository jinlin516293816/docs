React高频API详解 ​

一、核心Hook ​

1. useState ​

作用：在函数组件中添加状态管理

基本用法：

jsx
const [state, setState] = useState(initialState);
1

面试高频问题：

Q1: useState 的初始值什么时候生效？

  • 只在组件首次渲染时生效
  • 后续渲染会忽略初始值
  • 若初始值计算昂贵，应使用函数形式：useState(() => expensiveComputation())

Q2: setState 是同步还是异步？

  • 在事件处理函数中是异步的
  • 在 setTimeout/setInterval 中是同步的
  • 在 useEffect 中是异步的

Q3: 如何更新对象/数组状态？

jsx
// 对象更新
setUser(prev => ({ ...prev, name: 'New Name' }));

// 数组更新
setList(prev => [...prev, newItem]);

2. useEffect ​

作用：处理副作用（数据获取、订阅、DOM操作等）

基本用法：

jsx
useEffect(() => {
  // 副作用逻辑
  return () => {
    // 清理逻辑
  };
}, [dependencies]);

依赖数组的行为：

依赖数组执行时机
[]仅挂载时执行
[dep1, dep2]dep1 或 dep2 变化时执行
省略每次渲染都执行

面试高频问题：

Q1: useEffect 的执行顺序是什么？

  1. 首次渲染：组件挂载 → 执行所有 useEffect（按声明顺序）
  2. 更新渲染：执行清理函数 → 重新渲染 → 执行 useEffect

Q2: 如何避免 useEffect 中的无限循环？

  • 正确设置依赖数组
  • 使用 useCallback/useMemo 缓存引用类型依赖

Q3: useEffect 和 useLayoutEffect 的区别？

  • useEffect：在浏览器绘制后执行（异步）
  • useLayoutEffect：在浏览器绘制前执行（同步），会阻塞渲染

3. useContext ​

作用：跨组件传递数据，避免 props 逐级传递

基本用法：

jsx
// 创建 Context
const ThemeContext = createContext(defaultValue);

// 提供值
<ThemeContext.Provider value="dark">
  <Child />
</ThemeContext.Provider>

// 消费值
const theme = useContext(ThemeContext);

面试高频问题：

Q1: useContext 会导致不必要的重渲染吗？

  • 是的，当 Context 值变化时，所有消费该 Context 的组件都会重渲染
  • 解决方案：使用 useMemo 保持 Context 值的引用稳定

Q2: createContext 的 defaultValue 何时生效？

  • 只有当组件没有匹配到 Provider 时才会使用 defaultValue

4. useReducer ​

作用：管理复杂状态逻辑，替代 useState

基本用法：

jsx
function reducer(state, action) {
  switch (action.type) {
    case 'increment':
      return { count: state.count + 1 };
    case 'decrement':
      return { count: state.count - 1 };
    default:
      throw new Error();
  }
}

const [state, dispatch] = useReducer(reducer, initialState);

面试高频问题：

Q1: useState 和 useReducer 如何选择？

  • useState：适合简单状态
  • useReducer：适合复杂状态逻辑、状态转换有多种方式、需要集中管理

Q2: useReducer 的 dispatch 是稳定的吗？

  • 是的，dispatch 在组件生命周期内保持稳定，不会导致不必要的重渲染

5. useCallback ​

作用：缓存函数引用，避免不必要的重渲染

基本用法：

jsx
const memoizedCallback = useCallback(() => {
  doSomething(a, b);
}, [a, b]);

面试高频问题：

Q1: useCallback 和 useMemo 的区别？

  • useCallback：缓存函数本身
  • useMemo：缓存函数的返回值

Q2: 什么时候需要使用 useCallback？

  • 传递给使用 React.memo 的子组件
  • 作为 useEffect 的依赖

6. useMemo ​

作用：缓存计算结果，避免重复计算

基本用法：

jsx
const memoizedValue = useMemo(() => {
  return computeExpensiveValue(a, b);
}, [a, b]);

Q1: useMemo 会造成额外的内存开销吗？

  • 是的，会占用内存存储缓存值
  • 应仅在计算确实昂贵时使用

Q2: useMemo 的缓存何时失效？

  • 当依赖项发生变化时失效
  • 组件卸载时释放

三、面试高频问题汇总 ​

1. Hook 规则 ​

Q: 使用 Hook 必须遵循哪些规则？

  • 只在函数组件顶层调用 Hook
  • 只在 React 函数中调用 Hook
  • 不要在循环、条件或嵌套函数中调用

Q: 为什么要遵循这些规则？

  • 保证 Hook 调用顺序的一致性
  • 确保状态正确关联

2. 闭包陷阱 ​

Q: 什么是闭包陷阱？如何避免？

jsx
// ❌ 闭包陷阱
useEffect(() => {
  const timer = setInterval(() => {
    console.log(count); // 始终打印初始值
  }, 1000);
  return () => clearInterval(timer);
}, []);

// ✅ 解决方案：使用 ref
const countRef = useRef(count);
countRef.current = count;

useEffect(() => {
  const timer = setInterval(() => {
    console.log(countRef.current); // 正确获取最新值
  }, 1000);
  return () => clearInterval(timer);
}, []);

3. 性能优化 ​

Q: React 中有哪些性能优化手段？

  1. React.memo - 组件记忆
  2. useMemo - 计算结果缓存
  3. useCallback - 函数引用缓存
  4. React.lazy + Suspense - 代码分割
  5. 虚拟列表 - 大数据量渲染
  6. 避免不必要的重渲染

4. 状态更新 ​

Q: setState 的批量更新机制是什么？

  • 在事件处理函数中，多个 setState 会被批量处理
  • 异步更新，不会立即反映到 state

5. Context 性能优化 ​

Q: 如何优化 Context 导致的性能问题？

  • 将 Context 拆分为多个小 Context
  • 使用 useMemo 保持 Context 值的引用稳定
  • 使用 selector 模式只订阅需要的值

6. Hook 实现原理 ​

Q: Hook 是如何实现的？

  • 使用链表存储 Hook 状态
  • 依赖调用顺序来匹配状态
  • 通过 Fiber 架构实现状态管理

7. 自定义 Hook ​

Q: 什么是自定义 Hook？有什么优势？

  • 复用组件逻辑的函数
  • 优势：逻辑复用、代码清晰、易于测试

四、实战技巧 ​

1. 自定义 Hook 最佳实践 ​

jsx
// ✅ 好的做法：单一职责
function useFetch(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    const fetchData = async () => {
      try {
        const response = await fetch(url);
        const result = await response.json();
        setData(result);
      } catch (err) {
        setError(err);
      } finally {
        setLoading(false);
      }
    };

    fetchData();
  }, [url]);

  return { data, loading, error };
}

2. 状态管理模式 ​

jsx
// 使用 useReducer + Context 实现简单状态管理
const initialState = { count: 0 };

function reducer(state, action) {
  switch (action.type) {
    case 'increment':
      return { count: state.count + 1 };
    case 'decrement':
      return { count: state.count - 1 };
    default:
      return state;
  }
}

const CountContext = createContext(null);

export function CountProvider({ children }) {
  const [state, dispatch] = useReducer(reducer, initialState);
  return (
    <CountContext.Provider value={{ state, dispatch }}>
      {children}
    </CountContext.Provider>
  );
}

export function useCount() {
  const context = useContext(CountContext);
  if (!context) {
    throw new Error('useCount must be used within CountProvider');
  }
  return context;
}
