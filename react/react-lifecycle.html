React生命周期详解 ​

一、生命周期概述 ​

React 组件的生命周期分为三个阶段：

阶段描述包含方法
挂载阶段组件首次渲染到 DOMconstructor, getDerivedStateFromProps, render, componentDidMount
更新阶段组件状态或 props 变化getDerivedStateFromProps, shouldComponentUpdate, render, getSnapshotBeforeUpdate, componentDidUpdate
卸载阶段组件从 DOM 移除componentWillUnmount

二、类组件生命周期 ​

1. 挂载阶段 ​

jsx
class App extends React.Component {
  // 1. 构造函数 - 初始化状态
  constructor(props) {
    super(props);
    this.state = { count: 0 };
  }

  // 2. getDerivedStateFromProps - 从 props 派生状态
  static getDerivedStateFromProps(props, state) {
    // 返回新状态或 null
    return props.initialCount !== state.count ? { count: props.initialCount } : null;
  }

  // 3. render - 渲染组件
  render() {
    return <div>{this.state.count}</div>;
  }

  // 4. componentDidMount - 组件挂载完成
  componentDidMount() {
    // 发起网络请求、订阅事件等
    this.timer = setInterval(() => {
      this.setState(prev => ({ count: prev.count + 1 }));
    }, 1000);
  }
}

2. 更新阶段 ​

jsx
class App extends React.Component {
  // 1. getDerivedStateFromProps - 在每次渲染前调用
  static getDerivedStateFromProps(props, state) {
    return null;
  }

  // 2. shouldComponentUpdate - 决定是否重新渲染
  shouldComponentUpdate(nextProps, nextState) {
    // 返回 true 则更新，false 则跳过
    return nextState.count !== this.state.count;
  }

  // 3. render - 重新渲染
  render() {
    return <div>{this.state.count}</div>;
  }

  // 4. getSnapshotBeforeUpdate - 在 DOM 更新前获取快照
  getSnapshotBeforeUpdate(prevProps, prevState) {
    // 返回值会传递给 componentDidUpdate
    return prevState.count;
  }

  // 5. componentDidUpdate - 组件更新完成
  componentDidUpdate(prevProps, prevState, snapshot) {
    // 处理更新后的副作用
    console.log('Previous count:', snapshot);
  }
}

三、函数组件生命周期（Hooks 方式） ​

1. useEffect 模拟生命周期 ​

jsx
import { useState, useEffect } from 'react';

function App() {
  const [count, setCount] = useState(0);

  // 模拟 componentDidMount - 仅挂载时执行
  useEffect(() => {
    console.log('Component mounted');
    return () => {
      console.log('Cleanup before unmount');
    };
  }, []);

  // 模拟 componentDidUpdate - count 变化时执行
  useEffect(() => {
    console.log('Count updated:', count);
  }, [count]);

  // 模拟 componentWillUnmount - 清理函数
  useEffect(() => {
    const timer = setInterval(() => {
      setCount(c => c + 1);
    }, 1000);

    return () => {
      clearInterval(timer); // 清理
    };
  }, []);

  return <div>{count}</div>;
}

2. useLayoutEffect vs useEffect ​

jsx
function App() {
  const [width, setWidth] = useState(0);

  // useLayoutEffect - 同步执行，阻塞渲染
  useLayoutEffect(() => {
    const handleResize = () => setWidth(window.innerWidth);
    window.addEventListener('resize', handleResize);
    return () => window.removeEventListener('resize', handleResize);
  }, []);

  // useEffect - 异步执行，不阻塞渲染
  useEffect(() => {
    console.log('Width updated:', width);
  }, [width]);
}

四、React 内部原理 ​

1. Fiber 架构 ​

Fiber 是什么？

  • React 16 引入的新协调引擎
  • 实现增量渲染和时间切片
  • 将渲染工作拆分成小块，分散到多个帧

Fiber 节点结构：

javascript
const fiber = {
  type: Component,      // 组件类型
  key: null,           // 唯一标识
  stateNode: null,     // DOM 节点或组件实例
  child: null,         // 第一个子节点
  sibling: null,       // 下一个兄弟节点
  return: null,        // 父节点
  pendingProps: {},    // 新的 props
  memoizedProps: {},   // 旧的 props
  memoizedState: null, // 组件状态
  effectTag: null,     // 副作用标签
};

2. 调和算法（Reconciliation） ​

Diff 策略：

  1. 同层比较：只比较同一层级的节点
  2. 类型比较：类型不同则重建子树
  3. key 比较：通过 key 识别节点身份

Diff 过程：

旧树:                    新树:
<A>                      <A>
  <B>                      <C>
  <C>                      <B>
</A>                     </A>

// 无 key：B -> C, C -> B (两次更新)
// 有 key：B 和 C 交换位置 (一次移动)

工作原理：

4. 时间切片（Time Slicing） ​

实现原理：

javascript
function workLoop(deadline) {
  while (nextUnitOfWork && deadline.timeRemaining() > 0) {
    nextUnitOfWork = performUnitOfWork(nextUnitOfWork);
  }
  
  // 还有剩余工作，请求下一帧
  if (nextUnitOfWork) {
    requestIdleCallback(workLoop);
  }
}

// 启动工作循环
requestIdleCallback(workLoop);

  if (!component._isBatching) {

六、面试高频问题 ​

Q1: React 16 前后生命周期有什么变化？ ​

React 16 之前（旧版）：

  • componentWillMount
  • componentWillReceiveProps
  • componentWillUpdate

React 16 之后（新版）：

  • 引入 Fiber 架构
  • 新增 getDerivedStateFromProps（静态方法）
  • 新增 getSnapshotBeforeUpdate
  • 标记三个旧方法为 unsafe（可能在并发模式下被调用多次）

Q2: getDerivedStateFromProps 的使用场景？ ​

正确场景：

  • 当状态完全依赖于 props 时
  • 需要根据 props 变化同步更新状态

错误场景：

  • 用于处理副作用（应该用 useEffect）
  • 用于网络请求（应该用 componentDidMount/componentDidUpdate）
jsx
// ✅ 正确用法
static getDerivedStateFromProps(props, state) {
  if (props.id !== state.id) {
    return { id: props.id, data: null };
  }
  return null;
}

Q3: shouldComponentUpdate 和 React.memo 的区别？ ​

  • shouldComponentUpdate：类组件使用，可自定义比较逻辑
  • React.memo：函数组件使用，默认浅比较，可传入自定义比较函数

Q4: 为什么 componentWillMount 中不能发起网络请求？ ​

  1. 在服务端渲染中会被调用两次
  2. 会导致副作用与渲染耦合
  3. React 建议在 componentDidMount 中发起请求

Q5: Fiber 如何实现时间切片？ ​

  • 使用 requestIdleCallback API
  • 将渲染工作拆分成多个小单元
  • 在浏览器空闲时执行，不阻塞主线程

Q6: 什么是协调（Reconciliation）？ ​

  • React 对比新旧虚拟 DOM 的过程
  • 通过 Diff 算法找出最小变更
  • 高效更新真实 DOM

Q7: setState 是同步还是异步？ ​

官方回答： setState 不一定是同步的，React 会批量处理更新以提高性能。

具体表现：

  • 在事件处理函数中：异步
  • 在 setTimeout/setInterval 中：同步
  • 在原生事件处理中：同步

Q8: 如何强制组件重新渲染？ ​

jsx
// 类组件
this.forceUpdate();

// 函数组件 - 使用 key 变化
<Component key={Math.random()} />

// 函数组件 - 使用状态更新
const [, forceUpdate] = useState(0);
forceUpdate(n => n + 1);

1. 优先使用函数组件和 Hooks ​

jsx
// ✅ 推荐：函数组件 + Hooks
function App() {
  const [count, setCount] = useState(0);
  
  useEffect(() => {
    const timer = setInterval(() => {
      setCount(c => c + 1);
    }, 1000);
    return () => clearInterval(timer);
  }, []);
  
  return <div>{count}</div>;
}

jsx

3. 合理使用生命周期方法 ​

场景推荐方法
初始化状态constructor / useState
网络请求componentDidMount / useEffect
DOM 操作componentDidMount / useEffect
清理工作componentWillUnmount / useEffect 返回函数
性能优化shouldComponentUpdate / React.memo

八、总结 ​

React 生命周期是理解组件行为的关键：

  1. 类组件：提供完整的生命周期钩子，但代码冗余
  2. 函数组件：通过 Hooks 实现生命周期，代码简洁
  3. Fiber 架构：实现增量渲染，提升大型应用性能
  4. Diff 算法：高效更新 DOM，减少不必要的重绘

深入理解生命周期和内部原理，能够帮助你编写更高效、更可维护的 React 应用。
