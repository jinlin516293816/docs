Redux 详解 ​

一、Redux 核心概念 ​

1. 什么是 Redux？ ​

Redux 是一个用于管理 JavaScript 应用状态的容器。它提供了可预测的状态管理，使得状态变化变得可追踪和可测试。

核心原则：

  • 单一数据源：整个应用的状态存储在一个单一的 Store 中
  • 状态是只读的：只能通过触发 Action 来修改状态
  • 使用纯函数来修改状态：Reducer 是纯函数，接收旧状态和 Action，返回新状态

2. Redux 工作流程 ​

Action → Dispatcher → Reducer → Store → View
     ↑                                      │
     └──────────────────────────────────────┘
1
2
3

详细流程：

  1. View 层通过 dispatch(action) 触发一个动作
  2. Store 接收到 Action，将其转发给 Reducer
  3. Reducer 根据 Action 的类型返回新的状态
  4. Store 更新状态并通知所有订阅者
  5. View 层重新渲染

const initialState = {
  count: 0,
  name: 'Counter'

function counterReducer(state = initialState, action) {
  switch (action.type) {
    case 'INCREMENT':
      return { ...state, count: state.count + 1 };
    case 'DECREMENT':
      return { ...state, count: state.count - 1 };
    case 'SET_NAME':
      return { ...state, name: action.payload };
    default:
      return state;
  }
}

export default counterReducer;

四、Redux 中间件 ​

1. 什么是中间件？ ​

中间件是在 Action 到达 Reducer 之前执行的函数，用于处理日志、异步操作、路由等。

中间件签名：

javascript
const middleware = (store) => (next) => (action) => {
  // 在 dispatch 之前执行
  console.log('Action:', action);
  
  // 调用下一个中间件或 reducer
  const result = next(action);
  
  // 在 dispatch 之后执行
  console.log('New State:', store.getState());
  
  return result;
};

import { takeLatest, call, put } from 'redux-saga/effects';
import { fetchUserApi } from '../api';

// Worker Saga
function* fetchUserSaga(action) {
  try {
    const user = yield call(fetchUserApi, action.payload);
    yield put({ type: 'FETCH_USER_SUCCESS', payload: user });
  } catch (error) {
    yield put({ type: 'FETCH_USER_FAILURE', payload: error.message });
  }
}

// Watcher Saga
export function* watchUserSaga() {
  yield takeLatest('FETCH_USER_REQUEST', fetchUserSaga);
}

六、Redux 面试题 ​

问题 1：Redux 的三大原则是什么？ ​

答案：

  1. 单一数据源：整个应用的状态存储在一个单一的 Store 对象中
  2. 状态是只读的：唯一修改状态的方式是触发 Action
  3. 使用纯函数修改状态：Reducer 必须是纯函数，不产生副作用

问题 2：Redux 和 Context API 的区别？ ​

答案：

维度ReduxContext API
适用场景大型应用，复杂状态管理简单跨组件通信
状态追踪完整的时间旅行调试无
中间件支持支持（thunk、saga等）不支持
性能优化精细的订阅控制可能导致不必要的重渲染
学习成本较高较低

问题 3：为什么 Redux 使用纯函数？ ​

答案：

  • 可预测性：相同输入总是产生相同输出
  • 可测试性：纯函数易于单元测试
  • 可追溯性：状态变化完全由 Action 决定
  • 无副作用：不修改外部状态，不依赖外部环境

问题 4：Redux Thunk 的作用是什么？ ​

答案： Redux Thunk 允许 Action Creator 返回一个函数而不是一个 Action 对象。这个函数可以执行异步操作，然后在适当的时候 dispatch 真正的 Action。

使用场景：

  • 数据获取（API 调用）
  • 延迟操作
  • 条件 dispatch

问题 5：Redux Toolkit 解决了什么问题？ ​

答案：

  1. 样板代码过多：简化了 Action 和 Reducer 的编写
  2. 不可变状态麻烦：内置 Immer，允许直接修改状态
  3. 配置复杂：提供 configureStore 简化配置
  4. 异步操作繁琐：createAsyncThunk 简化异步逻辑

问题 6：Redux 和 MobX 的区别？ ​

答案：

维度ReduxMobX
状态管理集中式分散式
更新方式显式 dispatch Action自动响应式
可预测性高中等
学习曲线较陡较平缓
性能优化需要手动优化自动追踪依赖

问题 7：如何优化 Redux 应用性能？ ​

答案：

  1. 使用 reselect 创建记忆化选择器
  2. 使用 React.memo 避免不必要的重渲染
  3. 拆分 Reducer，按需订阅
  4. 使用 Immutable 数据结构
  5. 避免在 render 中创建新对象

问题 8：什么是 reselect？ ​

答案： reselect 是一个用于创建记忆化选择器的库，可以避免不必要的计算。

javascript
import { createSelector } from '@reduxjs/toolkit';

const selectUsers = (state) => state.users.list;
const selectFilter = (state) => state.users.filter;

// 记忆化选择器
const selectFilteredUsers = createSelector(
  [selectUsers, selectFilter],
  (users, filter) => {
    return users.filter(user => user.name.includes(filter));
  }

问题 9：Redux 的时间旅行是什么？ ​

答案： 时间旅行是 Redux 的一个强大特性，允许你：

  • 撤销/重做状态变化
  • 回放 Action 序列
  • 调试时跳转到任意时间点

实现原理：

  • 每次状态变化都被记录
  • 通过重新执行 Action 序列来恢复状态

问题 10：如何在 Redux 中处理错误？ ​

答案：

  1. 在 Reducer 中添加错误状态
  2. 在异步 Action 中捕获错误
  3. 使用错误边界组件
  4. 全局错误处理中间件
javascript
// 错误处理中间件
const errorMiddleware = (store) => (next) => (action) => {
  try {
    return next(action);
  } catch (error) {
    console.error('Redux Error:', error);
    store.dispatch({ type: 'ERROR', payload: error });
  }
};

七、完整 Demo：待办事项应用 ​

javascript
// store/slices/todoSlice.js
import { createSlice, createAsyncThunk } from '@reduxjs/toolkit';

// 异步获取待办事项
export const fetchTodos = createAsyncThunk('todos/fetchTodos', async () => {
  const response = await fetch('/api/todos');
  return response.json();
});

// 添加待办事项
export const addTodo = createAsyncThunk('todos/addTodo', async (text) => {
  const response = await fetch('/api/todos', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ text })
  });
  return response.json();
});

const todoSlice = createSlice({
  name: 'todos',
  initialState: {
    list: [],
    loading: false,
    error: null
  },
  reducers: {
    toggleTodo: (state, action) => {
      const todo = state.list.find(t => t.id === action.payload);
      if (todo) {
        todo.completed = !todo.completed;
      }
    },
    deleteTodo: (state, action) => {
      state.list = state.list.filter(t => t.id !== action.payload);
    }
  },
  extraReducers: (builder) => {
    builder
      .addCase(fetchTodos.pending, (state) => {
        state.loading = true;
      })
      .addCase(fetchTodos.fulfilled, (state, action) => {
        state.loading = false;
        state.list = action.payload;
      })
      .addCase(fetchTodos.rejected, (state, action) => {
        state.loading = false;
        state.error = action.error.message;
      })
      .addCase(addTodo.fulfilled, (state, action) => {
        state.list.push(action.payload);
      });
  }
});

export const { toggleTodo, deleteTodo } = todoSlice.actions;
export default todoSlice.reducer;

  };

  if (loading) return <div>Loading...</div>;
  if (error) return <div>Error: {error}</div>;

  return (
    <div>
      <form onSubmit={handleSubmit}>
        <input
          type="text"
          value={inputValue}
          onChange={(e) => setInputValue(e.target.value)}
          placeholder="Add a todo..."
        />
        <button type="submit">Add</button>
      </form>
      
      <ul>
        {list.map((todo) => (
          <li key={todo.id}>
            <input
              type="checkbox"
              checked={todo.completed}
              onChange={() => dispatch(toggleTodo(todo.id))}
            />
            <span style={{ textDecoration: todo.completed ? 'line-through' : 'none' }}>
              {todo.text}
            </span>
            <button onClick={() => dispatch(deleteTodo(todo.id))}>Delete</button>
          </li>
        ))}
      </ul>
    </div>
  );
}

export default TodoList;

八、总结 ​

Redux 适用场景：

  • 大型应用
  • 需要跨组件共享状态
  • 需要状态变化可追踪
  • 需要服务端渲染支持

替代方案：

  • Zustand：更轻量的状态管理
  • Jotai：基于原子的状态管理
  • MobX：响应式状态管理
  • Context API：简单的跨组件通信

学习路径：

  1. 理解 Redux 三大原则
  2. 掌握基本使用（Action、Reducer、Store）
  3. 学习中间件（Thunk、Saga）
  4. 掌握 Redux Toolkit
  5. 学习性能优化技巧
