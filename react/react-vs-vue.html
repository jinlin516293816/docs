React与Vue区别 ​

一、框架定位与设计理念 ​

React ​

  • 定位: 用于构建用户界面的 JavaScript 库
  • 设计理念: 函数式编程、单向数据流、虚拟 DOM
  • 核心思想: "Learn once, write anywhere"

Vue ​

  • 定位: 渐进式 JavaScript 框架
  • 设计理念: 响应式编程、双向数据绑定
  • 核心思想: 渐进式、易用性、灵活性

二、核心特性对比 ​

React - 单向数据流 ​

jsx
// 父组件传递数据给子组件
function Parent() {
  const [count, setCount] = useState(0);
  return <Child count={count} onUpdate={setCount} />;
}

// 子组件通过回调更新父组件状态
function Child({ count, onUpdate }) {
  return (
    <button onClick={() => onUpdate(c => c + 1)}>
      {count}
    </button>
  );
}

九、为什么 Vue 中 key 可以用 index，而 React 不能用？ ​

问题背景 ​

在列表渲染中，我们经常需要为每个元素指定一个 key 属性。常见的做法有两种：

  1. 使用数据的唯一标识（如 id）
  2. 使用数组索引（index）

为什么 React 强烈不建议使用 index 作为 key，而 Vue 相对宽松？

核心原因：Diff 算法的差异 ​

React 的 Diff 算法 ​

React 使用单向链表遍历的 Diff 算法，特点如下：

  1. 只能从左到右遍历，无法进行双端比较
  2. 完全依赖 key 来识别节点
  3. 无法复用位置变化的节点
React Diff 流程：
┌─────────────────────────────────────────────────────────┐
│  旧列表: [A, B, C]                                       │
│  新列表: [C, A, B]                                       │
│                                                         │
│  如果 key 是 index：                                     │
│  - 旧 key[0]=A, 新 key[0]=C → 认为是 A 变成了 C         │
│  - 旧 key[1]=B, 新 key[1]=A → 认为是 B 变成了 A         │
│  - 旧 key[2]=C, 新 key[2]=B → 认为是 C 变成了 B         │
│  结果：3 次更新，0 次移动                                │
│                                                         │
│  如果 key 是 id：                                        │
│  - 识别出 C 移动到了第一位                               │
│  - 结果：2 次移动，0 次更新                              │
└─────────────────────────────────────────────────────────┘

Vue 的 Diff 算法 ​

Vue 2 使用双端比较算法，Vue 3 使用最长递增子序列算法：

Vue 2 双端比较：

同时从新旧列表的两端开始比较：
- 旧头 vs 新头
- 旧尾 vs 新尾
- 旧头 vs 新尾
- 旧尾 vs 新头

即使 key 是 index，也能通过节点内容匹配找到移动的节点

2. 计算最长递增子序列
3. 只移动不在子序列中的节点

即使 key 是 index，Vue 3 也会尝试通过节点内容进行匹配

React - index 作为 key 的问题 ​

jsx
import { useState } from 'react';

function ReactKeyDemo() {
  const [items, setItems] = useState([
    { id: 1, name: 'Item 1', value: '' },
    { id: 2, name: 'Item 2', value: '' },
    { id: 3, name: 'Item 3', value: '' }
  ]);

  const [useIndexAsKey, setUseIndexAsKey] = useState(true);

  const addItem = () => {
    const newId = Math.max(...items.map(i => i.id)) + 1;
    setItems([{ id: newId, name: `Item ${newId}`, value: '' }, ...items]);
  };

  const removeFirst = () => {
    setItems(items.slice(1));
  };

  const reverseItems = () => {
    setItems([...items].reverse());
  };

  return (
    <div style={{ padding: '20px' }}>
      <h3>React Key Demo</h3>
      
      <label>
        <input 
          type="checkbox" 
          checked={useIndexAsKey}
          onChange={(e) => setUseIndexAsKey(e.target.checked)}
        />
        使用 index 作为 key
      </label>
      
      <div style={{ margin: '10px 0' }}>
        <button onClick={addItem}>头部添加</button>
        <button onClick={removeFirst}>删除第一个</button>
        <button onClick={reverseItems}>反转列表</button>
      </div>

      <div style={{ border: '1px solid #ccc', padding: '10px' }}>
        {items.map((item, index) => (
          <div 
            key={useIndexAsKey ? index : item.id}
            style={{ 
              padding: '10px', 
              margin: '5px 0',
              background: '#f5f5f5',
              borderRadius: '4px'
            }}
          >
            <span style={{ fontWeight: 'bold' }}>
              {item.name} (key={useIndexAsKey ? index : item.id})
            </span>
            <br />
            <input 
              type="text"
              placeholder="输入内容测试状态"
              value={item.value}
              onChange={(e) => {
                const newItems = [...items];
                newItems[index].value = e.target.value;
                setItems(newItems);
              }}
              style={{ marginTop: '5px', padding: '5px', width: '200px' }}
            />
          </div>
        ))}
      </div>

      <div style={{ marginTop: '10px', color: '#666' }}>
        <p>测试步骤：</p>
        <ol>
          <li>在输入框中输入内容</li>
          <li>点击"反转列表"或"头部添加"</li>
          <li>观察输入框内容是否跟随正确的项目</li>
        </ol>
      </div>
    </div>
  );
}

面试官问："为什么 React 不能用 index 作为 key，而 Vue 可以？"

推荐回答：

"这个问题涉及到 React 和 Vue 的 Diff 算法差异。

React 使用单向链表遍历算法，完全依赖 key 来识别节点。当使用 index 作为 key 时：

  • 列表顺序变化会导致 key 对应关系错乱
  • React 会认为是新元素，导致不必要的重新渲染
  • 可能导致组件状态错乱（如输入框内容错位）

Vue 使用双端比较（Vue 2）或最长递增子序列（Vue 3）算法：

  • 可以通过节点内容进行匹配
  • 即使 key 变化，也能识别出是同一个节点移动了
  • 但在头部插入、反转等场景仍可能出现问题

所以实际上 Vue 也不建议使用 index 作为 key，只是 Vue 的算法能更好地处理某些场景，问题相对不那么明显。

最佳实践是：无论 React 还是 Vue，都应该使用数据的唯一标识符（如 id）作为 key。"
